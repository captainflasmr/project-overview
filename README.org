A central, sortable table of your git projects. =M-x project-overview= opens a =tabulated-list-mode= buffer with one row per project — the git repositories found under =project-overview-search-roots= — surfacing the kind of status you usually have to dig for:

#+begin_example
Project          Version  ChangeLog   Bugs  Branch      Git  Remote  Owner          M  Commit            Last Commit
ollama-buddy     7.5.3    2026-05-19  2/15  main        *    github  captainflasmr  ✓  2026-06-02 14:32  Add streaming response handler
simply-annotate  1.2.0    2026-05-31  4/9   develop ↑2       github  captainflasmr     2026-05-31 09:18  Fix overlay refresh on save
bank-buddy       0.3.1    2026-01-16        main             gitlab  somegroup         2026-01-16 21:05  Tidy up category parsing
#+end_example

The table opens sorted by =Commit= date/time, most recently committed first.

* What each column means

- *Version / ChangeLog* :: parsed from the first =** <date> *X.Y.Z*= heading in the project's =CHANGELOG.org=.
- *Bugs* :: =open/total= count from =BUGS.org= (=TODO=/=DOING= vs everything, including =DONE=). Highlighted when there are open items.
- *Branch / Git* :: current branch, =*= when the worktree is dirty, and =↑n=/=↓n= for commits ahead of / behind the upstream.
- *Remote* :: the forge hosting the =origin= remote — =github=, =gitlab=, =codeberg=, =bitbucket=, =sourcehut=, or the bare host for anything else.  Blank for repositories with no remote (local only).
- *Owner* :: the owner/user segment of the remote URL — e.g. the GitHub username or organisation (=alice= for =github.com/alice/repo=).
- *GitHub* :: open issue/PR counts for GitHub-hosted repositories (e.g. =3i 1p=), fetched asynchronously with the =gh= CLI.  A project with new, unread issues or PRs is highlighted (name in red) and flagged with a leading =●= until acknowledged.
- *M (MELPA)* :: =✓= when a package matching the project's directory name is available from MELPA; blank otherwise.
- *Commit* :: date and time of the last commit (=YYYY-MM-DD HH:MM=), giving a granular default sort.
- *Last Commit* :: the subject (first line) of the most recent commit message.
- *Description* :: the first sentence of the project's =README.org= (or =README.md=), collapsed to a single line.

Click a column header (or press =S=) to sort by it.

A header line shows aggregate status across all projects, e.g.:

#+begin_example
 42 projects · 5 dirty · 3 out of sync · 28 open bugs in 9
#+end_example

The counts cover the full set regardless of any active filter.

The mode line shows the full (abbreviated) path of the project under point, updating as you move between rows.

* Actions

Single keys act on the project under point.  =o= opens the =project-switch-project= dispatch for that project, so its file-finding and shell commands are not duplicated here:

| Key         | Action                                        |
|-------------+-----------------------------------------------|
| =RET= / =o= | project dispatch (=project-switch-project=)   |
| =v= / =SPC= | =project-vc-dir=                              |
| =m=         | =magit-status=                                |
| =D=         | dired at root                                 |
| =.=         | detail card in a window to the right          |
| =C=         | open =CHANGELOG.org= in a window to the right |
| =b=         | open =BUGS.org= in a window to the right      |
| =B=         | TODO agenda scoped to this project's bugs     |
| =A=         | TODO agenda for every project's bugs          |
| =i= / =P=   | open GitHub issues / PRs in a side buffer     |
| =M=         | mark this project's new GitHub items as seen  |
| =/=         | filter the view (transient)                   |
| =g=         | refresh (re-scan)                             |
| =?=         | transient menu of all the above               |

* Cache and pull

These commands live in the =?= dispatch (they are not bound directly in the dashboard):

| Key | Action                                    |
|-----+-------------------------------------------|
| =p= | force-refresh GitHub issue/PR counts      |
| =L= | force-refresh the MELPA package list      |
| =a= | re-scan and force-refresh everything      |
| =G= | =git pull= every repository with a remote |
| =u= | =git pull= the project under point        |
| =c= | clear the on-disk cache                   |

A normal refresh (=g=) reuses cached network data while it is fresh; these commands force a re-fetch or clear the cache.  Network data (the MELPA list and per-repository GitHub counts) is cached in =project-overview-cache-file= for =project-overview-cache-ttl= seconds, so it survives restarts.

* GitHub integration

For GitHub-hosted projects the =GitHub= column shows the open issue and PR counts (via the =gh= CLI, which must be installed and authenticated).  =i= (=project-overview-github-issues=) and =P= (=project-overview-github-prs=) open the project's open issues or pull requests in an Org buffer — one heading per item with author, creation date, labels, URL, and body — in the shared right-hand window.  =w= opens the repository itself in a browser.

Whenever a repository's GitHub data is re-fetched (a forced pull, or the first fetch after =project-overview-cache-ttl= expires), the newest open issues and PRs are compared with the numbers seen at the previous fetch.  Items raised in the meantime are brought to your attention:

- the project name is highlighted (face =project-overview-github-new=) and a =●= marks its =GitHub= column;
- the header line adds a =N new= count; and
- a one-line summary is echoed, per =project-overview-github-notify=: =message= (the default) for an echo-area summary, =all= to also raise a desktop notification via =notifications-notify=, or =nil= for the markers only.

New-activity markers persist across restarts (they live in the same on-disk cache as the counts) until you acknowledge them with =M= (=project-overview-github-mark-seen=) on the project under point, or =C-u M= for every project.  Press =/ N= to list just the projects with new activity.

* Filtering

Press =/= (=project-overview-filter-dispatch=) to narrow the table to a different view of your repositories:

| Key | View                                               |
|-----+----------------------------------------------------|
| =d= | only repos with uncommitted changes                |
| =b= | only repos with open =BUGS.org= entries            |
| =u= | only repos ahead of / behind their upstream        |
| =o= | only repos owned by =project-overview-github-user= |
| =m= | only repos whose package is available on MELPA     |
| =g= | only repos with open GitHub issues or PRs          |
| =N= | only repos with new (unread) GitHub activity       |
| =n= | only repos whose name matches a regexp             |
| =/= | clear the filter (show all again)                  |

While a filter is active it is shown in the header line (=⦅ filter: dirty — 5 shown ⦆=) and in the mode line as =[dirty 5/42]=.  The whole header line uses the theme's =header-line= face, so it stays readable on any theme.  Filters are remembered across =g= (refresh), so you can keep, say, the "dirty" view live while you work through it, and clear it with =/ /= when done.

Prefer a menu? =?= (=project-overview-dispatch=) opens a transient with the same actions grouped into columns, headed by the project under point.

* Detail card

Press =.= (=project-overview-show-detail=) to open a per-project "card" in a window to the right — an Org buffer that gathers everything the dashboard knows about the project under point into one place:

- status: version and changelog date, branch and git state, last commit, remote (host / owner / repo), MELPA flag, open GitHub issue/PR counts (when fetched), and the README description;
- the open =BUGS.org= headings; and
- the ten most recent commits.

It reuses the already-scanned data, so it is near-instant — handy for a quick "what is going on with this repo?" without switching to it.

All of the right-hand views — the detail card, the =CHANGELOG.org=/=BUGS.org=/README visits (=C=/=b=/=R=) and the GitHub issue/PR panels (=i=/=P=) — share a single side window: opening another reuses that one window rather than splitting off a new one.  None of them take focus, so point always stays on the dashboard and you can keep moving down the list to flip through projects.

* Scanning

By default the dashboard scans *incrementally*: it appears immediately and fills each project's git/CHANGELOG/BUGS data in a few-at-a-time on a short timer, so Emacs stays responsive even with dozens of repositories.  A =scanning N/M= indicator shows in the header line while this runs, and rows keep the previous scan's values until they are re-probed.

- =project-overview-async-scan= :: non-nil (default) for incremental scanning; nil for a single blocking pass.
- =project-overview-async-batch-size= :: projects processed per timer tick (default 4) — larger finishes sooner but yields to input less often.

* Installation

#+begin_src emacs-lisp
(use-package project-overview
  :ensure nil
  :load-path "~/.emacs.d/offline-packages/local-packages/project-overview"
  :commands (project-overview)
  :custom
  (project-overview-search-roots
   (list "~/source/repos" "~/.emacs.d"))
  ;; Hide noise such as kernel source trees.
  (project-overview-exclude-regexp "\\`\\(linux-\\|melpa\\|themes\\'\\)"))
#+end_src

* Customization

- =project-overview-search-roots= :: directories scanned for git projects.  Each root is checked directly and one level deep for =.git= subdirs.
- =project-overview-exclude-regexp= :: project directory names matching this regexp are hidden.
- =project-overview-buffer-name= :: name of the dashboard buffer.
- =project-overview-show-github= :: when non-nil (the default), fetch open issue/PR counts for GitHub repositories with the =gh= CLI.
- =project-overview-github-notify= :: how to announce newly raised GitHub issues and PRs — =message= (the default), =all= (also a desktop notification), or =nil= (dashboard markers only).  See [[GitHub integration]].
- =project-overview-github-user= :: your GitHub username; its repositories' open issue/PR totals are summarised in the header line and the "owned by me" filter (=/ o=) uses it.
- =project-overview-show-description= :: when non-nil, show the wide =Description= column in every view (hidden by default).

* Notes

The =CHANGELOG.org= and =BUGS.org= parsing assumes the common org layout:

#+begin_example
#+todo: TODO DOING | DONE
* Versions
** <2026-05-19 Tue> *7.5.3*
#+end_example

but degrades gracefully when a file is missing or differently shaped.
